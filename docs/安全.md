# 安全说明:您的账号信息如何被保护(需求 4)

## 1. 凭据存放位置

| 信息 | 存放处 | 谁能读 |
|---|---|---|
| clientSecret(企业版)、refreshToken(个人版) | Cloudflare **KV**(静态加密) | 仅 Worker 运行时;您本人(经 wrangler)。**前端代码、浏览器、GitHub 仓库都拿不到** |
| ACCESS_PASSWORD / GATE_SECRET | Workers Secrets | 仅 Worker 运行时 |
| access_token | KV,约 55 分钟自动过期 | 同上 |

- 代码仓库**永远不含**任何密钥与账户标识符:配置由占位符模板生成(见 §4),`.gitignore` 已排除 `.dev.vars`、`.env*`、`.wrangler/`、生成物 `worker/wrangler.jsonc`。
- 所有 Graph API 调用都发生在 Worker 侧,浏览器只与 `/api/*` 通信,**任何 token 都不会下发到前端**。

## 2. 访客能看到什么

| 内容 | 是否可见 | 说明 |
|---|---|---|
| 您设置的展示名(如"一号机") | ✅ | 这本来就是展示用途 |
| 文件/文件夹名、大小、修改时间 | ✅ | 展示用途 |
| **临时下载直链** | ✅ | Graph 预授权链接,约 1 小时自动失效,泄漏了也会很快作废 |
| 您的账号邮箱/UPN | ❌ | 接口与页面均不返回 |
| clientSecret / refreshToken | ❌ | 仅在 KV |

注意两点(如实告知):

1. **企业版直链的主机名**形如 `<租户名>-my.sharepoint.com`,理论上访客可从链接看出您的租户名;个人版直链主机名不含账号标识。若介意,可自行增加"代理下载模式"(让流量经 Worker 中转,隐藏直链来源)——未实现,需要时按 plan.md §7 追加认领。
2. **Office 在线预览**把临时直链传给微软官方渲染服务 `view.officeapps.live.com`;文件本就存于 OneDrive,微软并不新增知情面。

## 3. 防滥用

- 建议开启站点密码(见 docs/setup-cloudflare.md §3):Cookie 为 HMAC 签名、HttpOnly、SameSite=Lax,服务端常量时间比较;密码试错按 IP 限速(KV 计数)。
- 直链本身有时效(≈1h),且下载流量走 OneDrive 而非 Cloudflare,刷直链消耗的是微软的带宽。

## 4. 仓库开源检查清单

本项目设计为可公开开源:配置由 `worker/wrangler.template.jsonc`(占位符)生成,真实 KV id 只在部署/开发时经环境变量注入,**新增内容永远不含标识符与凭据**。公开前做一次检查:

1. **git 历史扫描**(一次性):搜索历史中是否曾提交过真实 id / 密钥:
   ```bash
   git log -p --all | grep -iE "clientSecret|refreshToken|ACCESS_PASSWORD=.*[^\s]" # 密钥类: 应无结果
   ```
   - 本项目当前状态:凭据类**从未入库**;但早期手动填写的两个 KV namespace id 曾随 `worker/wrangler.jsonc` 入库(该文件现已改为生成物不入库)。KV id 只是标识符不是凭据,泄漏本身无害;若追求彻底零暴露,公开前二选一:
     - **轮换**:创建两个新 KV 命名空间 → `account:sync` 迁移数据 → 用新 id 更新 Secrets/构建变量 → 删除旧命名空间(历史里的旧 id 随之作废);
     - **改写历史**:`git filter-repo` 移除该文件的历史记录后 force-push(个人项目可行,协作者需重新克隆)。
2. **工作区扫描**:`git grep -riE "<真实id|secret|token>" --exclude-dir=.wrangler`,确认无命中;
3. 确认 `.dev.vars`、`.wrangler/`、`worker/wrangler.jsonc`(生成物)均被 gitignore 且未入库:`git status` 应看不到它们;
4. 确认 Cloudflare API Token 只存在于 GitHub Secrets / Workers Builds 构建变量中,未写进任何文件。

## 5. 您应做的事

- Azure 侧遵循最小权限:个人版只勾 `Files.Read.All + offline_access + User.Read`;企业版可用 `Sites.Selected` 代替 `Files.Read.All`(见 docs/setup-azure.md)。
- 定期轮换企业版 client secret(如每 6 个月)。
- Cloudflare 账号开启两步验证;`wrangler login` 的凭据不要共享。
- 若怀疑 refreshToken 泄漏:在 Azure 门户吊销该应用的刷新令牌(企业应用 → 用户设置/吊销),再用脚本重新授权。
